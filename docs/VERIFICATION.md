# 검증 기록

환경: Apple M4 Pro, 메모리 48 GB, macOS 27.2.1, Swift 6.4.2.

## 2026-11-17 README 등 영어 원문 표기

- 한국어 고정(`language: ko`, `WithLanguage("ko")`)을 제거하고 두 플랫폼에 언어 자동 감지를 적용했습니다.
  번역을 활성화하지 않으며 Mac은 `task: transcribe`, Windows는 기본 전사 작업을 유지합니다.
- README·GitHub·API 등 14개 개발 용어를 힌트 앞에 추가하고 단어 경계·한국어 조사를 확인해 음차를 보정합니다.
  `리드미컬한`, `리듬 위에`, 사람 이름 `제이슨`, 영어 일반 동사 `react`와 명사 `python`, 코드·URL·파일명 보존을 검사합니다.
- 공유 표기 fixture 35개로 결과·재보정·비활성화를 확인했습니다. Mac 코어 244개, Windows 코어 128개 통과.
  Mac SDK 검사 158개 통과: 언어 자동 감지·원어 전사·힌트 토큰 예산과 실시간 힌트 미노출 포함.
- Windows Release 크로스 컴파일 경고·오류 0개. Windows 샘플 추론 진단도 앱의 실제 자동 언어·용어 힌트 경로를 사용하도록 변경했습니다.
- macOS 시스템 음성 합성으로 만든 영어 4.53초·한국어 5.95초 파일을 실제 앱의 `--stream-file`로 검사했습니다.
  영어 최종 결과는 `Please update the README file on GitHub and keep the API examples in English.`,
  한국어는 `README 파일을 수정하고 GitHub에 올려주세요. API 사용 예제도 정리해주세요.`였습니다.
  기존 FLEURS 한국어 13.08초 샘플도 한국어로 전사했습니다. 테스트 오디오는 `var/qa/english-terms`에만 보관합니다.
- macOS 0.4.2(빌드 7)를 기존 개인 서명으로 설치했습니다. 기존 모델을 사용하며 모델 재다운로드는 없습니다.
  Windows 버전은 0.5.0-preview.2입니다. 이 기록은 실제 사용자 마이크의 정확도 보장을 의미하지 않습니다.

  x64 INPUT 레이아웃·유니코드 이벤트 구조, CPU 음성 추론과 ZIP 감사를 모두 통과했습니다.

  코드 서명·공증은 미완료로 공개 문서에 명시했습니다. Mac 기존 설치 앱은 교체하지 않았습니다.

## v0.4.1 실시간 용어 힌트 노출 수정

- 사용자 보고: 말하지 않은 Qwen·Ollama·RAG 등의 용어 목록이 미리보기에 나타나고
  실제 발화가 가려졌습니다. v0.4.0의 문자열 보정 검사는 이 경로를 다루지 못했습니다.
- 원인: WhisperKit 1.1.1 `TextDecoder`는 `currentTokens`에 힌트와 실제 전사를 함께
  보관합니다. 중간 `progress.text`는 특수 토큰만 제외하므로 힌트 문자열이 남습니다.
  최종 결과는 이미 `startOfTranscriptToken`부터 분리하고 있었습니다.
- 실시간 결과도 전사 시작·끝 토큰 경계로 분리합니다. 힌트만 있는 콜백은 표시하지
  않으며, 실제로 발화한 기술 용어는 보존합니다. 이전 문장을 유지하는 미리보기 동작과
  Qwen 모델명·크기 보정은 유지했습니다. 종료된 디코딩의 늦은 콜백도 무시합니다.
- 코어 회귀 검사 **138개 통과**. 힌트만 있는 입력, 첫 발화, 타임스탬프,
  실제로 말한 힌트 단어, 종료 경계, 잘못된 토큰과 경계 누락을 추가로 검사했습니다.
- `--check-preview`의 **106개 통과**. 설치한 Whisper 사전과 SDK의 실제
  `prefillDecoderInputs`를 사용해 기존 힌트 노출을 재현한 뒤, 미리보기 연결까지 검사했습니다.
  일반 한국어, Qwen·Ollama·RAG 발화, 용어 목록 자체를 발화한 경우, 사용자 추가 용어,
  힌트 비활성화와 타임스탬프 유무를 포함합니다. 이 검사는 모델 추론 검사가 아닙니다.
- Release 컴파일, 임시 번들 패키징·서명 무결성, Info.plist와 셸 문법 검사 통과.
  Swift 소스의 Sendable 경고 없이 빌드했습니다.
- FLEURS 한국어 파일의 실시간 추론도 시도했으나, 모델 로딩 후 샌드박스에서
  `Failed to create IOSurface-backed pixel buffer for MLMultiArray`로 실패했습니다.
  로그는 로컬 `var/qa/preview-audio-check.txt`에 있습니다. 실제 음성 인식 정확도와
  마이크 화면 동작은 이 결과로 검증 완료라고 간주하지 않습니다.
- 설치용 빌드는 로컬 서명 키체인 잠금 해제에 실패했습니다. 기존 설치 앱 v0.4.0은
  교체되지 않았습니다. 사용자 세션에서 업데이트 명령을 실행하면 고정 서명과 재실행을
  수행하고, 모델이 준비된 경우 미리보기 검사 결과를 `var/qa/preview-check.txt`에 남깁니다.

## v0.3.1 단축키 입력 검증

- 현재 저장된 조합이 `⌃⌘Space`임을 확인했습니다. 이 조합은 macOS의
  이모지·기호 창 단축키입니다. 또한 이 Mac의 시스템 단축키 설정에
  `⌃Space`, `⌃⌥Space` 입력 언어 전환이 활성화돼 있음을 확인했습니다.
- 기본 조합을 `⌃⇧Space`로 변경했습니다. 시스템 단축키 충돌을 확인하고,
  기존 설정이 충돌하면 백업 후 추천 조합을 등록하며 변경을 안내합니다.
- 기존 `held` 집합은 키 해제 이벤트 하나가 빠지면 다음 누름도 계속 무시했습니다.
  Carbon 누름 이벤트를 직접 처리하고 이벤트 시각으로 중복·오래된 이벤트만 걸러냅니다.
- Carbon 핸들러가 메인 스레드에서 순서대로 처리하도록 변경했습니다.
  핸들러 설치 오류, 이벤트 서명·ID, 등록 결과를 검사합니다.
  독점 등록으로 다른 앱과의 충돌을 확인하고 새 등록이 성공한 뒤 기존 등록을 해제합니다.
- 코어 검사 43개 통과. 단축키 충돌, 키 해제 누락, 연속 100회 누름,
  중복·역순 이벤트, 독립적인 취소 이벤트 검사를 포함합니다. Release 컴파일 성공.
- `--check-hotkeys`로 실제 Carbon 등록과 앱 내부 이벤트 전달 검사를 추가했습니다.
  자동 실행 환경에서는 전역 등록이 `eventInternalErr(-9868)`로 실패했습니다.
  이 결과는 아래 사용자 세션 검증과 구분합니다.
- 앱 화면 제어도 시간 초과로 실패했습니다. 설정에 녹음 없는 **단축키 검사**와
  수신 횟수를 추가해 사용자 세션에서 확인할 수 있습니다.
- 고정 인증서 키체인 잠금 해제가 자동 실행 환경에서 실패했습니다. 이후 사용자 세션에서
  업데이트가 실행돼 설치 앱 버전이 v0.3.1로 변경된 것을 확인했습니다.
  빌드는 서명·검증을 임시 폴더에서 마친 뒤에만 기존 앱을 교체하도록 변경했습니다.

  추천 조합 충돌 없음, Carbon 통합 검사 15개 및 연속 이벤트 100/100회 전달 통과.
  물리 키보드 5회 입력 결과와 실제 음성 정확도는 별도 확인 대상입니다.

## v0.3.0 미리보기와 권한 처리

- 다음 디코딩이 짧은 첫 단어부터 다시 시작해도 이전 문장을 지우지 않습니다.
  빈 중간 결과와 뒤늦게 온 짧은 콜백을 무시하고, 완료된 결과의 교정은 반영합니다.
- 미리보기를 380 × 252pt로 줄였습니다. 네이티브 텍스트 뷰를 유지하며
  화면 반영을 초당 최대 10회로 묶고, 줄이 늘어날 때만 하단 스크롤을 따라갑니다.
- 권한 없는 AX 조회를 막고 시스템 권한 요청 팝업을 한 번만 호출하도록 변경했습니다.
  설정에서 허용한 권한은 1.5초 간격으로 확인해 화면에 반영합니다.
- 기존 앱의 서명은 ad-hoc이며 지정 요구사항이 실행 파일 해시에 묶여 있음을 확인했습니다.
  프로젝트 전용 인증서와 고정 요구사항을 사용하는 서명·재실행 도구를 추가했습니다.
- v0.3.0 Release 빌드, 22개 코어 검사, 코드 서명 무결성, Info.plist와 셸 문법 검사를 통과했습니다.
- 자동 실행 환경의 키체인 생성이 실패해 현재 배포 앱은 아직 임시 서명입니다.
  `scripts/launchers/VoicePrompt 권한 고치기.command`를 사용자 세션에서 실행한 뒤 인증서 서명과
  권한 유지, 실제 화면의 전환을 확인해야 합니다. 고정 서명 적용 완료로 간주하지 않습니다.

- 작업 샌드박스에서 기존 GUI 프로세스에 보내는 종료 신호는 권한 오류로 거부되어,
  사용자 세션에서 재실행 명령을 수행하도록 안내했습니다.

## 확인한 항목

- Release 빌드 및 `VoicePrompt.app` 패키징 성공.
- `codesign --verify --deep --strict`와 Info.plist 형식 검사 통과.
- 실제 다국어 Whisper large-v3 turbo 모델과 한국어 지원 사전 다운로드 완료.
- 모델과 사전의 로컬 로딩 성공.
- 22개 코어 검사 통과: 부분 결과 교체, 확정 구간 유지, 최종 음성 반영,
  시간 기반 중복 방지, 실제 발화 반복 보존, 180초 구간 누적, 무음·짧은 잡음 제외,
  취소된 세션 결과 거부, 재인식 중 문장 유지와 최종 교정 반영.
- 사용자 확인: 설정 화면 표시와 녹음·전사 결과 표시.

## 최신 수정 후 확인할 항목

- 디코더 중간 글자가 말하는 도중 미리보기에 표시되는지.
- 같은 앱·창에 커서를 유지했을 때 수동 복사 없이 삽입되는지.
- Codex, ChatGPT 데스크톱, 브라우저 ChatGPT에서 각각 입력·선택 영역·클립보드 복원 확인.
- 실제 마이크로 한국어와 영어 기술 용어 혼용, 1~3분 발화, 끊김과 취소 확인.
- 네트워크를 끊은 상태에서 앱 재시작 후 전체 흐름 확인.

## 자동 검증 환경의 제한

컴퓨터 사용 도구의 ScreenCaptureKit 오류로 화면 캡처 검증을 완료하지 못했습니다.
독립 UI 렌더링도 현재 실행 샌드박스에서 AppKit 초기화 단계에 종료되었습니다.

공개 Google FLEURS 한국어 음성으로 추론을 시도했으나 현재 실행 샌드박스에서는
WhisperKit의 IOSurface 기반 MLMultiArray 할당이 실패했습니다. CPU 지정 시에도
SDK가 같은 메모리 경로를 사용해 실패했습니다. 따라서 자동 측정한 정확도·속도나
실시간 지연 수치는 아직 없습니다. 사용자가 직접 실행한 앱의 결과와 구분합니다.

검사용 음성 출처: https://huggingface.co/datasets/google/fleurs (ko_kr / dev).
검사용 파일은 `var/qa`에만 두며 배포 앱에 포함하지 않습니다.
